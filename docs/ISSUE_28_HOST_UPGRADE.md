# Issue #28：屏蔽酷安自身更新

对应 [issue #28](https://github.com/yylsping/coolapk-purifier/issues/28)。2.9.0 新增
“屏蔽酷安更新”，默认关闭，沿用宿主私有配置的原子保存与重启提示。

## 复现与控制点

在 PLQ110 / Android 17、酷安 16.7.0 上，实际复现了标题为“酷安-16.7.3”、
包含“取消 / 立即更新”的弹窗，与 issue 附图一致。原生
`SHOW_UPGRADE_DIALOG_TIME` 会在取消后抑制两天；测试对照只重置该时间，
不通过清除数据制造复现。原值在结束验收时恢复。

调用链由业务 DEX、原始调用引用和设备回调交叉确认：

1. 通用应用更新仓库将 `List<MobileApp>` 序列化为包名、版本号和 MD5 的
   JSON，Base64 编码后调用 `apk/checkUpdate`。
2. `CoolMarketApplication` 从自身 `MobileApp / UpgradeInfo` 读取可更新版本，
   构建升级弹窗。它还可能读取之前缓存的升级信息，因此仅过滤网络检查不足以
   覆盖弹窗。
3. “关于”的手动检查先改变页面状态，再发起单应用检查。
4. 升级按钮经 `ActionManager` 构造含 `PACKAGE_NAME` 的 `Extra`，进入
   下载调度入口，最终调用 `DownloadWorker`。16.7.3 中另一处三参 Worker
   调用属于停止下载，未作为新下载入口拦截。

## 实现

- 目标通过各版独立的 `hostUpgrade` 清单选择；未知版本不安装，不采用相邻
  版本或运行时模糊搜索。
- 检查列表只移除包名严格等于 `com.coolapk.market` 的条目。没有酷安时保留
  原列表身份；混合列表使用副本，保留其他条目、顺序及调用者列表。
- 仅含酷安的检查直接返回宿主自身的成功 `Result(emptyList)`，再由该版的
  Rx scalar 工厂包装，避免发送空检查请求，也保持下游的类型及完成语义。
- 独立拦截 Application 的自身升级弹窗入口，覆盖已有缓存。
- “关于”的检查在修改原生状态前返回，并显示“已屏蔽酷安更新检查”，避免
  留在“检查更新中”或误报“已是最新版本”。
- 下载调度仅在 `Extra.PACKAGE_NAME` 精确命中酷安时返回失败；其他应用及
  无法识别的参数透传。不会清理已有安装包。
- 安装前核对完整参数、返回值、静态性、非抽象及非 native 契约；四个 hook
  作为整体安装，失败回滚。回滚未成功的 handle 保留引用及账本，拦截器保持
  无效。关闭时透传原调用，启动时关闭则不安装业务 hook。

原有十项选择和底栏 mask 的迁移规则不变，新键 `block_self_update` 缺失时为
关闭。该功能不增加模块联网、后台组件、定时器或自更新能力；架构 gate 未放宽。

## 验证方法

单测覆盖包名精确匹配、混合列表、空列表、不可变输入、读取失败、方法契约
漂移、配置持久化、六版清单及缺失可选目标。设备验收另行检查开关双向、
原生手动更新恢复、清除原生提示抑制时间后的连续冷启动，以及其他净化功能。

临时运行时探针使用真实宿主模型、仓库和调度方法；测试期间将检查 API 和
下载 Worker 的末端隔离，避免真实网络或下载任务。它确认了仅检查酷安时
零 API 调用、成功空 Result、混合列表只发送其他应用、原列表不变、酷安下载
被拦截、其他应用下载透传，以及关闭后的检查和下载透传。探针已从交付源码
与 APK 移除，不是模块的常驻诊断功能。

完整设备矩阵与交付检查见 [16.7.3 适配记录](ADAPTATION_16_7_3.md)。
